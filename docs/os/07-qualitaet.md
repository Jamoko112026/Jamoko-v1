# 07 Qualität

## Zweck

Dieses Dokument beschreibt, wie JaMoKo Qualität sichert.

Qualität bedeutet: verständlich, ruhig, schnell, korrekt und vertrauenswürdig.

## Grundprinzip

Erst prüfen.

Dann veröffentlichen.

## Checkliste

- Funktionieren alle internen Links?
- Gibt es keine erreichbaren 404-Seiten?
- Funktioniert die mobile Ansicht?
- Sind CTAs klar und bedienbar?
- Stimmen Meta-Daten und H1?
- Sind Bilder geladen und sinnvoll beschrieben?
- Laufen `npm run lint` und `npm run build` bei Codeänderungen?

## Standards

- Änderungen klein halten
- visuelle Prüfung nach UI-Änderungen
- Build vor Abschluss
- rechtliche Seiten erreichbar halten
- Dokumentation bei wichtigen Entscheidungen aktualisieren

## Was wir vermeiden

- halb geprüfte Änderungen
- Designbruch
- Linkziele auf Verdacht
- unklare Abschlussberichte
- Livegang ohne einfache Prüfung
